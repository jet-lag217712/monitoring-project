# Local Mosquitto MQTT/TLS broker

The Equate appliance runs Eclipse Mosquitto as a private local delivery
boundary between collectors and ingestion. It is not a persistent monitoring
store; PostgreSQL remains authoritative.

## Generate local certificates

For source validation:

```bash
cd infrastructure/docker/mqtt-broker
chmod +x scripts/gen-dev-certs.sh scripts/gen-passwords.sh
./scripts/gen-dev-certs.sh
./scripts/gen-passwords.sh
docker compose up --build -d
```

Generated certificates and password files are gitignored. Production appliance
certificates and passwords are generated by the first-boot configuration under
the appliance runtime directory.

The broker listens on `tls://127.0.0.1:8883` in a source validation stack and
on the private `core` network inside the packaged appliance.

## ACL model

| User | Permission | Topic |
|---|---|---|
| `collector` | Publish | `site/+/device/+/telemetry/v2/#` |
| `collector` | Publish | `site/+/collector/+/telemetry/v2/heartbeat` |
| `ingestion` | Subscribe | `site/+/device/+/telemetry/v2/#` |
| `ingestion` | Subscribe | `site/+/collector/+/telemetry/v2/heartbeat` |

Anonymous access is disabled and TLS is required. The appliance creates unique
credentials per installation; never commit or reuse password files.

## Rotation

1. Generate a new password for the affected local broker account.
2. Update the corresponding runtime secret and collector/ingestion environment.
3. Restart Mosquitto, then ingestion and collectors.
4. Confirm `/readyz`, the TUI transport view, and a local v2 smoke or live poll.

Do not place private keys under tracked certificate directories. Keep the broker
and its administration surface on private appliance networks.

## Smoke subscribe

```bash
mosquitto_sub -h 127.0.0.1 -p 8883 \
  --cafile certs/ca.crt \
  -u ingestion -P '<local password>' \
  -t 'site/+/device/+/telemetry/v2/#' \
  -t 'site/+/collector/+/telemetry/v2/heartbeat' -v
```
